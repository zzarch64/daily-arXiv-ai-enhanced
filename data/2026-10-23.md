### [1] [Verified DRAM Address Mapping Reverse Engineering with Threshold Sweep](https://arxiv.org/abs/2610.30397)
*Hewen Zhang,Ian G. Harris*

Main category: cs.AR

TL;DR: 提出并实现了一个面向嵌入式LPDDR5系统的端到端流水线，用于求解与验证DRAM地址映射函数，通过阈值扫描、Knock-Knock线性约束求解、GF(2) RREF 及两级验证，系统记录各阈值下的候选bank掩码与验证指标，从而实现更稳健的映射恢复并服务于Rowhammer分析。


<details>
  <summary>Details</summary>
Motivation: 现有方法通常只返回单一推断映射，缺乏对求解结果正确性的系统验证与候选比较，在ARM嵌入式LPDDR5平台上映射恢复的鲁棒性不足；同时后续Rowhammer分析需要可靠的DRAM地址映射函数。

Method: 构建端到端软件流水线：从地址对的大规模延迟数据集出发，先构建延迟直方图，再进行阈值扫描以获得候选同bank地址对；对每个阈值应用Knock-Knock风格线性约束求解器恢复候选bank掩码，并用GF(2)简化行阶梯形（RREF）计算最终bank掩码；设计两级验证——组验证（检验恢复掩码诱导的bank划分与观测时序是否一致）与单函数验证（逐一移除某个地址函数并测量验证通过率变化）。

Result: 在嵌入式平台（ARM架构设备）上实例化该流水线，对每个候选阈值均系统记录求解得到的bank掩码及验证指标，从而支持在多个候选中进行更稳健的bank掩码选择，并实现DRAM地址映射函数的高效逆向工程。

Conclusion: 该工作提供了一种系统化、可验证的DRAM地址映射逆向流程，相较仅输出单一映射的做法具备更强的鲁棒性与可解释性，并为后续Rowhammer分析奠定基础。

Abstract: We propose an end-to-end software pipeline for solving and validating DRAM address mapping functions on embedded LPDDR5 systems, and we instantiate it on embedded platforms. Starting from a large latency dataset of address pairs, the pipeline first builds a latency histogram and then performs a threshold sweep to obtain candidate same-bank address pairs. For each threshold, we apply a Knock-Knock-style linear-constraint solver to recover candidate bank masks. Final bank masks are calculated using GF(2) reduced row echelon form (RREF). To verify correctness, we implement two verification stages, group verification and single function verification, inspired by prior work. Group verification checks whether bank partitions induced by the recovered masks agree with observed timing behavior. Single function verification removes one addressing function at a time and measures the resulting change in verification pass rate. Unlike approaches that return only a single inferred mapping, our workflow systematically records, for each candidate threshold, the solved bank masks and validation metrics. This pipeline supports more robust selection of bank masks on ARM-based embedded devices and provides an efficient method for reverse engineering DRAM address mapping functions and subsequent Rowhammer analysis.

### [2] [Proba: A High-Performance, Low-Traffic Probabilistic Spatial Memory Streaming Prefetcher](https://arxiv.org/abs/2610.30448)
*Yinting Huang,Jacky Wong,Sam Ainsworth*

Main category: cs.AR

TL;DR: 本文提出Proba，一种反馈驱动的SMS（空间内存流）预取器，通过概率化模式更新、边际精度决策和多触发特征模式累积，实现细粒度精度-覆盖率权衡，性能优于其他SMS类预取器且DRAM开销大幅降低。


<details>
  <summary>Details</summary>
Motivation: 现有SMS预取器存在两大缺陷：一是对预取激进度（aggressiveness）的控制过于粗糙，二是难以适应程序动态行为与历史访问模式。

Method: Proba采用反馈导向机制，包含三项关键设计：(1) 概率化模式更新；(2) 基于边际精度的决策；(3) 跨多个触发特征的模式累积。通过闭环反馈动态调节激进度：精度下降时收敛以优先保证准确预取，精度上升时扩大覆盖率。

Result: Proba在SMS类预取器中取得最高加速比，同时DRAM流量效率显著更优；在多核与DRAM受限场景下与其他技术拉开较大性能差距，且不损害单线程吞吐。

Conclusion: Proba通过细粒度的精度-覆盖率动态权衡，有效解决了SMS预取器的控制粒度与自适应性问题，在高效能与低带宽开销之间取得良好平衡。

Abstract: Spatial Memory Streaming (SMS) prefetchers exploit recurring spatial access patterns across memory regions to predict future accesses. Despite their effectiveness, existing SMS-based designs suffer from coarse control over aggressiveness and limited adaptability to dynamic program behavior and historical patterns. In this work, we present Proba, a feedback-directed SMS-based prefetcher that integrates probabilistic pattern updates, marginal accuracy decision-making, and pattern accumulation over several trigger features to achieve fine-grained accuracy-coverage trade-offs. When accuracy deteriorates, Proba moderates its aggressiveness to prioritize accurate prefetches; conversely, when accuracy rises, it expands its coverage. Proba achieves higher speedups than any other SMS-based prefetcher while being vastly more efficient in DRAM traffic. This culminates in a large performance gap between Proba and other techniques in multicore and DRAM-constrained scenarios without harming single-threaded throughput.

### [3] [FIGFLEX: A Mixed-Precision FP-INT GEMM Accelerator Co-Designed with Low-Bit LLM Quantization](https://arxiv.org/abs/2610.30480)
*Faraz Tahmasebi,Haocheng Xu,Andrew Trauger,Yomal Perera,Zhenyu Tang,Nael Chowdhury,Sitao Huang*

Main category: cs.AR

TL;DR: FIGFLEX是一个算法-硬件协同设计的混合精度加速器，通过移位-加法的radix-4重构FP-INT乘法与精度自适应量化器，使比特并行数据通路在低精度下提升吞吐，在LLaMA-2-7B上以3/2比特实现更低的困惑度并获得更高的单位面积吞吐。


<details>
  <summary>Details</summary>
Motivation: 权重-only量化将主要负载转为浮点-整数（FP-INT）GEMM，混合精度量化器已可达2-3比特平均精度，但硬件未跟上：GPU张量核在乘累加前需将权重反量化到FP16，而比特并行FP-INT加速器固定单一权重精度；因此减少比特只节省存储而不节省计算。

Method: （1）提出FP-INT乘法的移位-加法radix-4重构，将乘累加融合为统一、精度灵活的部分积归约，约减半部分积数量；并设计INT3优化，回收该精度下radix-4数据通路的空闲资源。（2）设计混合精度量化器：按GPTQ无法补偿的误差为每个通道组分配位宽；采用逐输入通道列缩放，其2的幂归一化使缩放后激活避开FP16次正规数范围，使量化模型可直接映射到FIGFLEX数据通路且精度与GPU一致。

Result: 在LLaMA-2-7B上，3比特和2比特平均精度下WikiText-2困惑度分别为5.85和8.77，优于GPTQ、AWQ、SliM-LLM、AMQ与QuIP#（无微调）；在3比特混合精度模型的线性GEMM上，整芯片单位面积吞吐分别比AxCore和FIGLUT高1.56倍和1.42倍。

Conclusion: 通过算法与硬件协同设计，FIGFLEX实现了随精度下降而扩展吞吐的比特并行数据通路，并保持与GPU量化一致的精度，验证了低精度下同时节省存储与计算的可行性与优越性。

Abstract: Weight-only quantization keeps LLM activations in floating point and stores weights as low-bit integers, turning the dominant workload into floating-point-integer (FP-INT) general matrix multiplication. Recent quantizers reach a 2-3-bit average with mixed precision, but hardware has not kept pace: GPUs dequantize weights to FP16 before the tensor-core multiply-accumulate, and bit-parallel FP-INT accelerators run at a single weight precision, so fewer bits save memory but not computation. In this paper, we present FIGFLEX, an algorithm-hardware co-designed mixed-precision accelerator whose bit-parallel datapath scales throughput as precision falls. FIGFLEX contributes (1) a shift-add, radix-4 reformulation of FP-INT multiplication that fuses the multiply-accumulate into a unified, precision-flexible partial-product reduction and roughly halves the partial products, together with a novel INT3 optimization that reclaims the idle datapath radix-4 leaves at that precision; and (2) a mixed-precision quantizer that assigns each channel group its bit-width according to the error GPTQ cannot compensate, with a per-input-channel column scaling whose power-of-two normalization keeps the scaled activations out of the FP16 subnormal range, so that the quantized model maps directly onto FIGFLEX's datapath with the same accuracy as on a GPU. On LLaMA-2-7B, FIGFLEX attains 5.85 and 8.77 WikiText-2 perplexity at 3- and 2-bit average precision, lower than GPTQ, AWQ, SliM-LLM, AMQ, and QuIP# (without fine-tuning), while delivering 1.56x and 1.42x higher whole-chip throughput per area on the linear GEMMs of a 3-bit mixed-precision model than AxCore and FIGLUT, respectively.

### [4] [HDLouvain: High-Throughput Incremental Clustering for Hyperdimensional Data](https://arxiv.org/abs/2610.30687)
*Beenish Gul,Mahbod Afarin,Farhat Ahmed,Sumukh Pinge,Tsung-Han Lu,Tajana Rosing,Kevin Skadron*

Main category: cs.AR

TL;DR: 提出 HDLouvain，将 Louvain 社区检测与超维计算(HDC)的位并行相似度计算结合，把 bootstrap 样本按前体质量分桶、对每桶 kNN 图跑 Louvain、用按位多数捆绑把社区压缩为单个二值超向量，新谱通过 GPU 汉明距离查表增量分配，实现流式蛋白质组学数据的可扩展高质量聚类。


<details>
  <summary>Details</summary>
Motivation: 现代鸟枪法蛋白质组学每小时产生数万张串联质谱、数百 GB 数据，传统聚类流程难以承受。DBSCAN 对密度变化不稳定，HAC 复杂度 O(n²)，二者簇质量差；Louvain 等图方法簇质量高但在流式数据上可扩展性差。

Method: HDLouvain：将 Louvain 与 HDC 的位并行相似度计算结合。把流的 bootstrap 比例 α 部分按前体质量分桶，对每桶 kNN 相似度图应用 Louvain；用按位多数捆绑(而非迭代重心重算)把每个社区浓缩为单个二值超向量作代表；新谱在其质量桶内用 GPU 加速的汉明距离查表匹配，未达相似度阈值 τ 则新建簇，从而增量扩展划分而无需全量重聚类。

Result: 在 5 个 PRIDE 数据集(0.99M–21.13M 谱)上，α 从 0.2 到 0.9 呈单调吞吐-保真度权衡。PXD003258 上加速比从 α=0.3 的 4.5x 到 α=0.7 的 1.65x；模块度从 α=0.2 的 0.75–0.76 升至 α=0.9 的 0.95–0.97，较全量静态重算最多低 8%。Louvain 阶段在 30k–2M 节点的 LFR 基准上 NMI 达 0.86–0.93，而 DBSCAN 与 HAC 退化至 0.57。

Conclusion: HDC 位并行相似度与社区代表捆绑能在不牺牲 Louvain 簇质量的前提下解决其可扩展性瓶颈，为大规模流式质谱数据提供高吞吐、高保真且可显式调节的增量聚类方案。

Abstract: Modern shotgun proteomics generates tens of thousands of tandem mass spectra per hour, producing hundreds of gigabytes of data that strain conventional clustering pipelines. DBSCAN and hierarchical agglomerative clustering (HAC) offer flexible similarity search, but DBSCAN is unstable across varying data densities, HAC costs $O(n^2)$, and both yield poor cluster quality. Graph-based methods such as Louvain produce high-quality clusters but scale poorly on streaming data. We observe that Louvain's poor scalability can be resolved without sacrificing its quality, and present HDLouvain, which combines Louvain community detection with the bit-parallel similarity computation of hyperdimensional computing (HDC). HDLouvain partitions a bootstrap fraction of the stream into precursor-mass buckets, applies Louvain to each bucket's kNN similarity graph, and condenses each community into a single binary hypervector by bitwise-majority bundling rather than iterative centroid recomputation. New spectra are assigned by a GPU-accelerated Hamming distance lookup against representatives in their mass bucket, or seed a new cluster when no match meets a similarity threshold $τ$, so the partition grows incrementally without full re-clustering. On five PRIDE datasets (0.99M to 21.13M spectra), sweeping the bootstrap fraction $α$ from 0.2 to 0.9 exposes an explicit, monotonic throughput-fidelity trade-off. On PXD003258, speedup ranges from 4.5x at $α=0.3$ to 1.65x at $α=0.7$. Modularity rises from 0.75-0.76 at $α=0.2$ to 0.95-0.97 at $α=0.9$, never more than 8% below full static recomputation. The Louvain stage achieves 0.86-0.93 normalized mutual information (NMI) on LFR benchmark networks with 30k to 2M nodes, whereas DBSCAN and HAC degrade to 0.57.

### [5] [SnakeCharmer: Orchestrating Utility, Timeliness, and Placement in GPU Prefetching](https://arxiv.org/abs/2610.30990)
*Yuhan Tang,Tiejun Li,Jianmin Zhang,An Hu,Guangyu Sun,Sheng Ma,Yiqun Lang,Hanqing Li,Siqing Fu*

Main category: cs.AR

TL;DR: 提出SnakeCharmer，一个面向地址预测型GPU预取器的统一后端预取控制框架，将地址预测与预取实现解耦，联合控制预取的有用性、及时性与存放位置，在A100模型上相比Snake提升性能/能效12.8%/20.8%，相比APOGEE提升1.7%/3.2%。


<details>
  <summary>Details</summary>
Motivation: GPU依赖大规模线程级并行掩盖长内存延迟，但当大量warp同时等待内存数据时仍会出现严重停顿。基于地址预测的预取器可缓解此类停顿，然而预测准确并不等于性能提升：预取只有"值得发出、时机正确、能被保留而不造成有害干扰"才有收益，而这三个需求相互耦合，孤立优化任一维度只会把瓶颈转移到别处。

Method: 以"从预测预取到实际收益"的视角建模需求，提出统一后端控制框架SnakeCharmer，把地址预测从预取实现中分离：前端预测器仅产生预取候选，后端控制路径联合决定是否发出、何时发出以及返回数据存放在何处。具体机制为：面向有用性的零值感知过滤（zero-value-aware filtering）、基于层次化反馈的预取距离调节（timeliness）、以及寄存器辅助的预取缓冲区（placement）。实现主要构建于Snake之上，并将同样的后端控制思想移植到APOGEE以验证框架的通用性。

Result: 在A100 GPU模型上，SnakeCharmer相比Snake提升性能/能效12.8%/20.8%，相比APOGEE提升1.7%/3.2%，硬件开销适中。

Conclusion: GPU预取的关键瓶颈不在于预测精度，而在于预取实现层面的效用、及时性与放置的联合控制；将预测与实现解耦的统一后端控制框架可跨不同前端预测器（Snake、APOGEE）带来稳定收益，且实现代价可控。

Abstract: GPUs rely on massive thread-level parallelism to tolerate long memory latency, yet they still suffer severe stalls when many warps simultaneously wait for data from the memory system. Address-prediction-based GPU prefetchers can mitigate such stalls, but accurate prediction alone does not guarantee performance improvement: a predicted prefetch becomes beneficial only if it is worth issuing, arrives at the right time, and is retained without harmful interference. Because these requirements interact, optimizing any single dimension in isolation can simply move the bottleneck to another.

SnakeCharmer separates address prediction from prefetch realization: the frontend predictor generates prefetch candidates, while the backend control path jointly controls utility, timeliness, and placement by determining whether each candidate should be issued, when it should be issued, and where the returned data should be retained. SnakeCharmer realizes this control path with zero-value-aware filtering for utility, hierarchical feedback-driven distance tuning for timeliness, and a register-assisted prefetch buffer for placement. We design and implement SnakeCharmer primarily on top of Snake, and adapt the same backend-control principles to APOGEE to demonstrate that SnakeCharmer's benefits are not limited to a single frontend predictor. On an A100 GPU model, SnakeCharmer improves performance/energy efficiency by 12.8%/20.8% over Snake and by 1.7%/3.2% over APOGEE, with modest hardware overhead.

### [1] [HyPAIC: Personal AI Computer with High Bandwidth Flash for High Performance Trillion-Parameter LLM Inference](https://arxiv.org/abs/2611.04144)
*Minho Ha,Myunghyun Rhee,Euiseok Kim,Hoshik Kim*

Main category: cs.AR

TL;DR: HyPAIC 是一种在个人 AI 计算机（PAIC）中引入 HBF（High Bandwidth Flash）的架构：只读模型权重存于 HBF、可变运行时数据存于 LPDDR，以突破 LPDDR 统一主存的容量瓶颈，并通过预取、只读权重布局与粗粒度访问缓解 HBF 的延迟、写耐久与页级粒度问题，从而在单设备上支撑万亿参数 MoE 推理。


<details>
  <summary>Details</summary>
Motivation: LLM 从聊天机器人演进为直接调用工具的 agentic AI，前沿模型多采用 MoE 架构并推至万亿参数规模。云推理存在成本与安全顾虑，推动本地部署需求，GPU 厂商因此推出 PAIC。但现有 PAIC 依赖 LPDDR 统一主存，容量严重受限：单设备可承载的模型规模有限，且权重占用大部分内存后，留给 KV cache 的空间很少，制约可支持的上下文长度。

Method: 提出 HyPAIC 架构，以 HBF 扩展 PAIC 内存层级：HBF 容量超过 HBM 10 倍且具备相近的 TB/s 级带宽。将只读模型权重放在 HBF，可变运行时数据放在 LPDDR。针对 HBF 三项缺陷分别应对：用预取应对访问延迟，用只读权重放置应对写耐久有限，用粗粒度权重访问应对页级访问粒度。功耗与散热被视为主要实现挑战。采用基于模拟的评估方法。

Result: 在 1T 参数 MoE 推理中，单台 HyPAIC 相较八台无 HBF 基线系统的聚合，端到端系统吞吐最高提升 1.04x，TDP 归一化吞吐最高提升 3.59x，即单机接近八台基线的原始性能且能效显著更优。小模型推理中，每任务维持至少 50 decode TPS 的最大并发任务数最高提升 4x，改善用户体验与生产力。

Conclusion: 尽管 HBF 规格仍在演进，研究表明 HBF 与 PAIC 之间存在显著的架构协同效应，HBF 可有效缓解 PAIC 的容量与 KV cache 空间约束，并以远优的能效在单设备上近似多机聚合性能；功耗与冷却是后续实现需重点解决的问题。

Abstract: LLMs have rapidly expanded from simple chatbots to agentic AI, where models directly use tools to solve complex problems. To improve problem solving, most frontier LLMs adopt an MoE architecture, pushing model sizes into the trillion-parameter regime. While cloud services have dominated large-scale LLM inference, cost and security concerns drive demand for on-premises deployment. Thus, GPU manufacturers have introduced personal AI computers (PAICs). However, existing PAICs with LPDDR-based unified main memory suffer from severe capacity limitations, restricting hostable LLM size on a single device. If most memory holds model weights, little remains for the KV cache, reducing supported context length. In this paper, we propose HyPAIC, a PAIC architecture incorporating HBF to overcome these memory constraints. HyPAIC stores read-only model weights in HBF and mutable runtime data in LPDDR. HBF offers over 10x the capacity of HBM with comparable TB/s-scale bandwidth. HyPAIC addresses HBF's access latency, limited write endurance, and page-level access granularity through prefetching, read-only weight placement, and coarse-grained weight accesses, respectively; power and cooling remain significant implementation challenges. Through simulation-based evaluation, we show that a single HyPAIC improves end-to-end system throughput by up to 1.04x and TDP-normalized throughput by up to 3.59x during 1T-parameter MoE inference versus the aggregate of eight baseline systems without HBF, one HyPAIC thus approaches the raw performance of eight baselines with far superior power efficiency. For small model inference, HyPAIC increases the maximum number of concurrent tasks sustaining at least 50 decode TPS per task by up to 4x, enhancing user experience and productivity. Although HBF specifications are still evolving, this study demonstrates strong architectural synergy between HBF and PAICs.

### [2] [GSPIM: A Temporal-Locality-Aware 4DGS Accelerator for PIM-Enabled Edge Devices](https://arxiv.org/abs/2611.04804)
*Zirui Ma,Zhihua Fan,Haibin Wu,Dongrui Fan,Xiaochun Ye,Wenming Li*

Main category: cs.AR

TL;DR: GSPIM：面向 PIM 边缘设备的时序局部性感知 4DGS 加速器，通过多态 PIM、多帧渲染数据流与混合调度，在几何平均上实现 4.15× 加速与 4.99× 能效提升。


<details>
  <summary>Details</summary>
Motivation: 现有 4DGS（显式 4D 分布、关键帧插值、锚点绑定等方法）存在两个 GPU 数据搬运瓶颈：一是时间过滤发生在模型记录加载之后，无效数据仍占用 LPDDR5 带宽；二是逐帧独立执行忽略了相邻帧高度重叠的活跃集合与深度关系，当工作集超过片上缓存容量时共享属性被反复重载。

Method: 提出 GSPIM，一种时序局部性感知的 4DGS 加速器，面向支持 PIM 的边缘设备：(1) 多态 PIM（Polymorphic PIM），将共享的近存数据通路适配到不同表示特有的字段布局与选择过程，在 GPU 访问完整属性前完成有效数据的过滤与紧凑化，形成连续输入；(2) 多帧渲染数据流（Multi-Frame Rendering Dataflow），在时间窗口内复用活跃属性与稳定深度关系；(3) 混合数据流调度（Hybrid Dataflow Scheduling），将近存数据准备与 GPU 渲染重叠以降低等待。

Result: 评估采用经 Jetson AGX Orin 64 GB 校准的 GPU-PIM 模型，并对新增电路进行 1z DRAM 物理实现。在三种 4DGS 方法与六个动态场景上，相对充分优化的逐帧 GPU 基线取得 4.15× 几何平均加速与 4.99× 几何平均能效提升；最大场景级 PSNR 差异为 0.011 dB；32 颗 LPDDR5 裸片上的新增物理面积为 18.7172 mm²。

Conclusion: 将时序局部性感知的近存计算引入 4DGS 渲染，可在几乎不损失画质（PSNR 差 ≤ 0.011 dB）与有限面积开销（18.7172 mm²）下显著缓解 LPDDR5 带宽与数据重载瓶颈，为边缘端实时自由视点视频、移动 XR 与自主系统提供可行路径。

Abstract: 4D Gaussian Splatting (4DGS) enables high-quality real-time novel-view synthesis for dynamic scenes, supporting free-viewpoint video, mobile XR, and autonomous systems at the edge. Methods using explicit 4D distributions, keyframe interpolation, or anchor binding share two GPU data-movement bottlenecks. Temporal filtering follows model record loading, wasting LPDDR5 bandwidth on inactive data. Frame-isolated execution also overlooks highly overlapping active sets and depth relationships across adjacent frames, reloading shared attributes when working sets exceed on-chip cache capacity. To address these bottlenecks, we present GSPIM, a temporal-locality-aware 4DGS accelerator for PIM-enabled edge devices. Polymorphic PIM adapts a shared near-memory datapath to representation-specific field layouts and selection procedures. It filters and compacts valid data into contiguous inputs before the GPU accesses complete attributes, reducing ineffective transfers. Multi-Frame Rendering Dataflow reuses active attributes and stable depth relationships within a temporal window, reducing repeated work across frames. Hybrid Dataflow Scheduling overlaps near-memory data preparation with GPU rendering to reduce waiting. Evaluation combines a GPU-PIM model calibrated to Jetson AGX Orin 64 GB with a 1z DRAM physical implementation of the added circuits. Across three 4DGS methods and six dynamic scenes, GSPIM achieves a 4.15x geometric-mean speedup and a 4.99x geometric-mean energy-efficiency improvement over a fully optimized frame-by-frame GPU baseline. The maximum scene-level PSNR difference is 0.011 dB, and the added physical footprint is 18.7172 square millimeters across 32 LPDDR5 dies.

### [1] [Fengshui: Demystifying Chiplet Ecosystem and Bespoke Neural Network Accelerator Codesign](https://arxiv.org/abs/2609.10970)
*Haoran Jin,Jirong Yang,Zhiheng Zhang,Justin Shin,Barry Lyu,Kangqi Zhang,Yunpeng Liu,Nathan Bleier*

Main category: cs.AR

TL;DR: 提出Fengshui芯片生态系统与加速器协同设计框架，通过算子级解聚与chiplet池/专用加速器联合优化，用8个chiplet实现接近无约束异构设计的能效表现。


<details>
  <summary>Details</summary>
Motivation: 现代ML负载对延迟和能耗要求严苛，在同构通用硬件上难以高效运行。算子级解聚（针对每个算子定制微架构、批处理与存储层次）是突破瓶颈的关键，但高度定制的加速器会带来难以承受的NRE成本。基于chiplet的集成可分摊NRE，然而"该造哪些chiplet"与"如何将其组合成加速器"存在循环依赖：chiplet池的价值取决于所构建的加速器，而加速器质量又受限于可用chiplet。

Method: Fengshui是一个chiplet生态系统与加速器协同设计框架，同时优化chiplet池组成与定制ASIC（BASIC）设计。它通过算子级解聚构建BASIC，协同探索chiplet与存储异构性、张量融合，以及流水线/张量/专家并行，并结合布局布线（place-and-route）验证以保证物理可实现性。

Result: 仅用8个策略性选取的chiplet（涵盖网络交换机、存内计算单元及多种微架构加速器），Fengshui生成的BASIC相比同构加速器在能量、EC、EDP、EDPC上分别降低48.5%、88.1%、93.0%、97.8%，并在多种神经网络上与无约束异构设计的差距在4.1%以内。面向数据中心MoE与稠密LLM服务，预填充能量与EC分别最多降低16.8%和28.7%；面向边缘自动驾驶感知，在实时延迟约束下实现12.0%能量与23.6% EC降低。

Conclusion: 通过在算子级解聚基础上对chiplet池与专用加速器进行联合协同设计，Fengshui以极小的chiplet规模大幅逼近无约束异构理想设计，验证了chiplet生态协同设计在克服NRE壁垒、满足ML负载严格延迟与能耗约束方面的有效性。

Abstract: Modern ML workloads, with stringent latency and energy constraints, are increasingly hard to run efficiently on homogeneous commodity hardware. We argue that operator-level disaggregation--tailoring microarchitecture, batching, and memory hierarchy to each operator--is essential to overcome these limitations, though the resulting highly bespoke accelerators incur prohibitive Non-Recurring Engineering (NRE) costs. Chiplet-based integration amortizes NRE across applications, but choosing which chiplets to build and how to compose them into accelerators is circularly dependent--a chiplet pool's value depends on the constructed accelerators, while accelerator quality is constrained by available chiplets. This paper introduces Fengshui, a chiplet ecosystem and accelerator co-design framework that jointly optimizes chiplet pool composition and bespoke application-specific integrated circuit (BASIC) design. Fengshui constructs BASICs through operator-level disaggregation, co-exploring chiplet and memory heterogeneity, tensor fusion, and pipeline/tensor/expert parallelism with place-and-route validation for physical implementability. With just 8 strategically selected chiplets, encompassing network switches, processing-in-memory units, and accelerators with diverse microarchitectures, Fengshui-generated BASICs achieve 48.5%, 88.1%, 93.0%, and 97.8% reductions in energy, energy-cost product (EC), energy-delay product (EDP), and energy-delay-cost product (EDPC) over homogeneous accelerators, while scoring within 4.1% of unconstrained heterogeneous designs across diverse neural networks. For datacenter MoE and dense LLM serving, Fengshui reduces prefill energy and EC by up to 16.8% and 28.7%, respectively; for edge autonomous vehicle perception, it achieves 12.0% energy and 23.6% EC reductions under real-time latency constraints.

### [2] [BEACON: A Versatile Accelerator for Computational Pathology Applications](https://arxiv.org/abs/2609.11044)
*Sumanth Gudaparthi,Ananth Krishna Prasad,Lin Jia,Rajeev Balasubramonian,Srinivasan Parthasarathy*

Main category: cs.AR

TL;DR: 本文提出"AI+X"思路：以基线AI加速器为基础，添加最小逻辑以支持新领域算子，从而以高量产通用芯片服务多类应用；并以计算病理学（Computational Pathology）为例设计了BEACON加速器。


<details>
  <summary>Details</summary>
Motivation: AI加速器已获商业成功，但其他专用领域难以复制这一成功，新加速器面临诸多壁垒（研发成本、量产规模、部署风险）。作者主张通过复用基线AI加速器并仅增加最小逻辑来降低门槛，获得可高量产、可多场景部署的通用芯片。

Method: 以计算病理学为验证领域：其多阶段流水线包含分割与特征提取、kNN图构建、以及交替Aggregation与Combination的迭代GCN推理。分析表明这些算子在基线CPU、GPU、AI及GCN加速器上执行效率低。作者通过软件重构加少量硬件改动予以解决：在基线脉动阵列AI加速器中提供PE间灵活数据通路与寄存器访问机制，并新增特征聚合、负载均衡执行、欧氏距离计算、分箱（binning）与计数器聚合等支持。

Result: 这些灵活性与逻辑使基线AI chiplet面积仅增长1.1倍；由于规避了内存墙并提供高并行度，BEACON在计算病理学工作负载上相较基线CPU与GPU平台取得超过一个数量级的吞吐量提升。

Conclusion: "AI+X"是降低新领域专用加速器门槛的可行路径：以极小面积代价扩展基线AI加速器，即可高效支撑计算病理学等多阶段、多算子流水线，实现显著吞吐收益。

Abstract: While accelerators for AI have seen great commercial success, it is challenging to replicate that success for other specialized domains due to a number of factors. We make the case that barriers for new accelerators can be lowered by starting with a baseline AI accelerator, and adding minimal logic to support new operators demanded by new specialized domains. This leads to a versatile chip that can be manufactured at high volume and deployed for a range of popular applications. We refer to this as the AI+X approach. This paper explores its potential for the emerging domain of Computational Pathology, which involves analysis of large whole-slide tissue images with a multi-stage pipeline. The pipeline requires support for a number of different kernels and operators - early stages perform segmentation and feature extraction, followed by graph creation with k nearest neighbor (kNN) algorithms, and finally inference with an iterative graph convolutional network (GCN) that alternates between Aggregation and Combination. We show that these stages execute inefficiently on a range of baseline CPU, GPU, AI, and GCN accelerators. That inefficiency is addressed with a combination of software re-structuring and small modifications to a baseline systolic AI accelerator. Many of the above kernels can be mapped to a systolic accelerator by offering a flexible datapath between processing elements and register access mechanisms. We add support for feature aggregation, load balanced execution, Euclidean distance calculation, binning, and counter aggregation. This additional flexibility and logic grows the area of a baseline AI chiplet by 1.1x, but by avoiding the memory wall and offering high parallelism, the proposed accelerator BEACON yields over an order of magnitude higher throughput for Computational Pathology than baseline CPU and GPU platforms.

</details>


### [3] [Bio-inspired Learning and Decision-Making with Probabilistic In-Memory Computing Hardware: Part 2](https://arxiv.org/abs/2609.11288)
*Thomas Dalgaty,Eiji Kawasaki,Miguel de Prado,Tommaso Salvatori,Germain Haugou,Eric Flamand*

Main category: cs.AR

TL;DR: 该报告（Part 2）指出，大规模概率能量基模型在GPU上因HBM接口导致严重延迟与扩展性瓶颈；作者构建了概率模拟存内计算（AIMC）处理器的事务级模型（TLM），证明消除HBM接口、在片上内存中直接计算后，同一能量基模型可实现超过1000倍于数据中心级硬件的加速。


<details>
  <summary>Details</summary>
Motivation: Part 1提出的基于随机Langevin动力学的能量基模型虽能持续演化神经元状态与权重的近似概率分布，但GPU实现确认其存在执行延迟过高的可扩展性问题。作者认为根源并非模型本身不可扩展，而是GPU依赖HBM接口的架构对低算术强度、高度并行的模型施加了强顺序执行约束，造成模型"不可扩展"的假象。

Method: 采用详细的事务级模型（transaction-level model, TLM）对一种概率模拟存内计算（probabilistic analogue in-memory computing, AIMC）处理器进行建模，将能量基模型的计算直接放在片上内存中执行，从而消除HBM接口这一瓶颈。

Result: 在同一能量基模型上，AIMC处理器的TLM仿真显示其执行速度可超过数据中心级硬件的1000倍。

Conclusion: 限制此类概率能量基模型扩展性的并非模型本身，而是依赖HBM接口的GPU架构；通过消除HBM接口、在片上内存内直接计算，AIMC架构可显著提升该类AI模型的执行效率与可扩展性。

Abstract: This report extends our previous work (Part 1), which introduced an energy-based model for learning and decision-making under uncertainty. The model leverages stochastic Langevin dynamics to continuously evolve approximate probability distributions over neuron states and model weights. However, as noted in Part 1 and confirmed through GPU-based implementations, large-scale probabilistic energy-based models of this nature face significant scalability challenges due to excessive execution latency. This latency stems from a fundamental mismatch: massively parallel models with low arithmetic intensity (such as energy-based models) are being executed on processor architectures like GPUs that rely on high-bandwidth memory (HBM) interfaces. The HBM imposes brutally sequential execution constraints on inherently parallelizable models, creating the false impression that such models are unscalable. In reality, it is the GPU architecture itself, with its dependence on HBM interfaces, that is not a scalable processor architecture for this class of AI model. In this report, we demonstrate using a detailed transaction-level model (TLM) of a probabilistic analogue in-memory computing (AIMC) processor that the same energy-based model can execute well over 1000x faster than data-center-grade hardware by eliminating the HBM interface and performing computation directly within on-chip memory.

### [4] [PATTON: Enabling Commodity PIM for Production LLM Serving](https://arxiv.org/abs/2609.11392)
*Hangyeol Kim,Sanghyun Lee,Teokkyu Suh,Joo-Young Kim*

Main category: cs.AR

TL;DR: PATTON 是一个面向商用 PIM 的运行时系统，通过层次化粒度分配与 Commit Zone 机制，在支持生产级 LLM 服务引擎完整 KV cache 生命周期的同时，兼顾 GEMV 效率、单 token 写入效率与内存容量，实现平均 1.95 倍加速和 4.83 倍能效提升。


<details>
  <summary>Details</summary>
Motivation: PIM 虽能加速访存受限的 decode attention，但仅加速 attention 不足以支撑生产级 LLM 服务：引擎需动态分配、填充、共享、缓存与回收逻辑 KV cache 块。在商用 PIM 上支持该生命周期需要高效的物理内存分配、块到地址映射与命令生成。对 Value cache 而言，GEMV 效率、单 token 写入效率与内存容量之间存在根本冲突：面向 GEMV 优化的布局会将新生成的 Value 向量分散到不同行导致写入昂贵，而更细粒度的内存共享虽提升容量利用率却会碎片化 GEMV 归约。

Method: PATTON 引入层次化粒度分配：块大小的 Key/Value 粒度与逻辑 token 块一一对应，固定其物理位置与命令；更粗粒度则聚合多个块以支持高效 GEMV 执行与内存利用。Commit Zone 暂存部分 Value 块以实现高效单 token 写入，再提交至 GEMV 优化位置。PATTON 跟踪这些布局以生成 KV cache 写入及 QK-transpose/SV 命令，且无需修改 PIM 处理单元。

Result: 在 attention 执行及运行时引发的 prefill 重计算场景下，PATTON 相较评估基线实现平均 1.95 倍加速与 4.83 倍能效提升，无需修改 PIM 处理单元，并保持与 vLLM 原生 GPU KV cache 相当的 KV cache 命中率。

Conclusion: PATTON 通过层次化粒度分配与 Commit Zone 机制，在商用 PIM 上有效调和了 GEMV 效率、单 token 写入效率与内存容量之间的冲突，为生产级 LLM 服务引擎提供高效且兼容的 PIM 运行时支持。

Abstract: Processing-in-Memory (PIM) is promising for accelerating memory-bound decode attention, but attention acceleration alone is insufficient for production LLM serving, where engines dynamically allocate, populate, share, cache, and reclaim logical KV cache blocks. Supporting this lifecycle on commodity PIM requires efficient physical memory allocation, block-to-address mapping, and command generation. For the Value cache, these requirements create a fundamental conflict among GEMV efficiency, single-token write efficiency, and memory capacity: GEMV-optimized layouts scatter newly generated Value vectors across rows, making writes costly, while finer-grained memory sharing improves capacity utilization but fragments GEMV reductions. We present PATTON, a PIM runtime that integrates production LLM serving engines with commodity PIM. PATTON introduces hierarchical granule allocation: block-sized Key and Value granules map one-to-one to logical token blocks, fixing their physical placements and commands, while coarser granules group blocks for efficient GEMV execution and memory utilization. A Commit Zone stages partial Value blocks for efficient single-token writes before committing them to GEMV-optimized locations. PATTON tracks these placements to generate KV cache writes and QK-transpose/SV commands. Across attention execution and runtime-induced prefill recomputation, PATTON achieves an average 1.95x speedup and 4.83x higher energy efficiency over evaluated baselines, requires no PIM processing-unit modifications, and maintains a KV cache hit rate comparable to the native GPU KV cache in vLLM.

</details>

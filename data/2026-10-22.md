### [1] [Accelerating CPU Speculative Decoding via Unified Graph Execution and Transactional KV Isolation](https://arxiv.org/abs/2610.28671)
*Zhangdie Yuan*

Main category: cs.AR

TL;DR: SubTernary 通过在单一内存 arena 中统一编译草稿/目标图并结合事务性 KV 缓存隔离，消除 CPU 上投机解码的上下文切换与内存分配瓶颈，实现 1.35×（相对 llama.cpp 投机解码）与 3.99×（相对自回归）加速，回滚延迟保持 O(1)。


<details>
  <summary>Details</summary>
Motivation: 投机解码可加速 LLM 推理，但部署于 CPU 时存在严重系统瓶颈：草稿图与目标图之间的上下文切换延迟，以及 KV 缓存回滚时的内存分配开销。

Method: 提出执行框架 SubTernary，包含两项核心技术：统一图缓存（将两模型编译进单一内存 arena，配合持久线程池，避免线程同步）与事务性 KV 缓存隔离（将投机 token 路由至静态 scratchpad，以零拷贝指针重置替代动态重分配）。并集成 256-bit AVX2 三元 SIMD 内核作为低位宽案例研究。

Result: 消融实验表明系统运行时贡献 35.0% 的吞吐增益，三元内核额外贡献 6.0%。整体实现相对 llama.cpp 投机解码 1.35× 加速、相对自回归解码 3.99× 加速，且回滚延迟为 O(1)。

Conclusion: 系统级优化（图缓存与 KV 隔离）是 CPU 端点投机解码的主要收益来源，低位宽内核为次要增益；该框架在保持常数级回滚延迟的同时取得显著端到端加速。

Abstract: Speculative decoding accelerates LLM inference, but deploying it on CPUs introduces severe systems bottlenecks: context-swapping latency between draft and target graphs, and memory allocation overhead during KV cache rollbacks. We introduce SubTernary, an execution framework that eliminates these costs through Unified Graph Caching and Transactional KV-Cache Isolation. By compiling both models into a single memory arena with a persistent thread pool and routing speculative tokens to a static scratchpad for zero-copy pointer resets, SubTernary avoids dynamic reallocation and thread synchronization entirely. We integrate a 256-bit AVX2 ternary SIMD kernel as a low-bit case study. Ablations reveal our systems runtime drives 35.0% of the throughput gains, while the ternary kernel adds 6.0%. SubTernary achieves a $1.35\times$ speedup over llama.cpp speculative decoding and $3.99\times$ over autoregressive decoding, maintaining $O(1)$ rollback latency.

Method: 从开源仓库及Verilog转换设计中构建18,500+条经语法校验的VHDL数据集；用参数高效QLoRA对5个7B参数LLM微调，以适应资源受限环境；建立三级评估流水线：语法与综合验证、基于testbench的功能仿真、Zynq SoC上的FPGA原型验证。

Abstract: The rapid evolution of digital circuit complexity demands innovative approaches to hardware design automation. Five 7B-parameter LLMs were fine-tuned using parameter-efficient QLoRA technique, enabling deployment in resource-constrained environments. To evaluate model efficacy, a rigorous three-level pipeline was established: (1) syntax and synthesis validation, (2) functional simulation with testbenches, and (3) FPGA prototyping on Zynq SoCs. Generated designs were successfully deployed on real hardware, confirming not only syntactic but operational viability. This work demonstrates that LLMs, when tailored with domain-specific data and lightweight fine-tuning can contribute meaningfully to the future of generative EDA workflows.

### [4] [Reorienting the Vector Axis: Restructuring FlashAttention for Long-Vector Processors](https://arxiv.org/abs/2610.29489)
*Emmanuel Irabor,Marc Casas*

Main category: cs.AR

TL;DR: 本文将 PyTorch 的 CPU FlashAttention 内核移植到 2KB 向量寄存器的 RISC-V 平台，提出"转置 score tile 与运行输出使 query 落在连续轴"及"将指数多项式系数移入标量寄存器"两项优化，使内核周期降低 1.84–2.08x，浮点利用率由 16.2% 提升至 29.7%。


<details>
  <summary>Details</summary>
Motivation: 注意力开销随序列长度平方增长并主导层耗时，FlashAttention 虽通过分块与在线 softmax 更新降低开销，但后续工作几乎都面向 GPU。在长向量处理器上（单寄存器可容纳 512 个单精度数），向量指令收益与其寄存器利用率成正比，因此"向量化哪个循环"成为一阶决策，而现有 CPU 内核在此平台上仅达峰值浮点吞吐的 16.2%，存在显著优化空间。

Method: 先剖析移植后内核的三处低效：以单个 query 行遍历 tile、沿 64 元素 head 维向量化；softmax 的逐行最大值与求和需将整个寄存器归约为标量；软件指数函数的多项式系数与 tile 数据争用向量寄存器导致溢出（spilling）。随后提出两项技术：(1) 转置 score tile 与运行输出，使 query 位于连续轴，算法与数值结果不变，仅由"每 tile 的 query 数"这一个参数统一决定内核各部分的向量长度并可适配硬件，同时消除两处归约；(2) 将多项式系数移入标量寄存器，消除溢出并使 softmax 的向量访存指令减少 78.7%。

Result: 在 64 的 head 维下，两项技术合计使整核周期降低 1.84–2.08x，浮点利用率从峰值 16.2% 提升至 29.7%；同设计的 FPGA 对两项改动的排序一致且得分更高，达 2.71x。

Conclusion: 在长向量 RISC-V 架构上，向量化的循环维度选择与寄存器压力管理是决定 FlashAttention 性能的关键；通过沿 query 轴向量化并释放向量寄存器压力，可在不改动算法与数值的前提下显著提升性能，且该结论在硅片与 FPGA 上一致可复现。

Abstract: A Transformer is built around attention, whose cost grows with the square of the sequence length and dominates the layer on long sequences. FlashAttention made that cost manageable by tiling the attention matrix and updating the softmax as it goes, but almost all work since has targeted GPUs. On long-vector processors one vector register can hold up to 512 single-precision numbers. The savings of a vector instruction are proportional to how much of the register it uses, so the choice of which loop to vectorize is a first-order decision. We port PyTorch's CPU FlashAttention kernel to a RISC-V CPU with 2KB vector registers and find that it reaches 16.2% of peak floating-point throughput. The kernel walks each tile one query row at a time: the product against V is vectorized along the 64-element head dimension, the softmax's per-row maximum and sum are reductions that collapse a full register to a scalar, and the software exponential's polynomial coefficients compete with tile data for vector registers and cause spilling. We propose two techniques. The first transposes the score tile and the running output so that queries lie along the contiguous axis. The algorithm and its values are unchanged. A single parameter, the number of queries in a tile, now sets the vector length of every part of the kernel and can be matched to the machine. Both reductions also disappear. The second moves the polynomial's coefficients into scalar registers, removing the spills and cutting the softmax's vector memory instructions by 78.7%. On silicon the two together cut whole-kernel cycles by 1.84 to 2.08x at a head dimension of 64, raising floating-point utilization from 16.2% to 29.7% of peak. An FPGA of the same design ranks the changes identically and scores them higher, at 2.71x.

### [6] [HAWK: Heterogeneity-Aware KV Cache Transfer for Efficient GPU-NPU Phase-Disaggregated LLM Inference](https://arxiv.org/abs/2610.29873)
*Junhyeok Park,Jungeun Yoon,Kyungmin Kim,Hunsoon Lee,Shinyoung Ahn,Kangho Kim*

Main category: cs.AR

TL;DR: 提出 HAWK：一种面向 GPU-NPU 异构 LLM 推理的 KV cache 跨设备传输机制，通过布局感知的 RDMA 缓冲区实现免重排直接消费，在满足 SLO 前提下性能达纯 GPU 系统 92% 以上，并提升能效 1.26×、成本效率 1.72×。


<details>
  <summary>Details</summary>
Motivation: LLM 推理两阶段计算特征不同：prefill 计算密集、decode 访存密集。GPU 擅长 prefill 但 decode 阶段利用率低，NPU 在 decode 阶段能更充分利用算力。因此考虑将 prefill 映射到 GPU、decode 映射到 NPU 的异构架构。但该方案的关键障碍是阶段解耦需将 KV cache 从 GPU 传到 NPU，而两设备在通信机制与 KV cache 张量布局上存在差异。

Method: HAWK 建立 RDMA 路径实现跨设备直接传输，并将张量布局差异的处理融入传输过程本身：在 NPU 侧分配与目标张量布局对齐的 RDMA 缓冲区，编排数据从 GPU 侧常规连续 RDMA 缓冲区传输到对应的 NPU 缓冲区，使接收张量可直接被消费而无需额外数据重排，同时保持传输效率。

Result: 在商用 GPU 与 NPU 构建的系统上实现并评估：在相同 SLO 约束下，性能与纯 GPU 系统差距在 7.88% 以内，同时能效最高提升 1.26×、成本效率最高提升 1.72×。

Conclusion: 异构 GPU-NPU 部署（GPU 做 prefill、NPU 做 decode）具有实际可行性，KV cache 跨设备传输是可行落地的关键；布局感知 RDMA 传输可在不牺牲传输效率与端到端性能的前提下，显著改善能效与成本效率。

Abstract: Large language model (LLM) inference exhibits distinct computational characteristics across its two phases: prefill is compute-intensive, whereas decode is more memory-bound. As a result, AI accelerators achieve varying levels of efficiency across the two phases. GPUs are well suited to prefill, but are often underutilized during decode. By contrast, NPUs can utilize their compute resources more effectively during decode. Motivated by this observation, we explore a heterogeneous architecture that integrates GPUs and NPUs, mapping prefill to GPUs and decode to NPUs to achieve high performance and efficiency. However, realizing such heterogeneous integration is challenging because LLM phase disaggregation requires KV cache transfer from prefill to decode (that is, from GPUs to NPUs), which is complicated by differences in inter-device communication mechanisms and KV cache tensor layouts.
  To address this, we propose HAWK, a transfer mechanism that enables rapid KV cache transfer across heterogeneous devices. HAWK establishes a remote direct memory access (RDMA) path for direct cross-device transfers while handling inter-device tensor layout discrepancies as part of the transfer process. In particular, HAWK allocates tensor-layout-aware RDMA buffers on the NPU side to match the target tensor layout. Leveraging these buffers, HAWK orchestrates data transfer from a conventional contiguous GPU RDMA buffer to the corresponding NPU buffers, allowing transferred tensors to be consumed directly without additional data rearrangement while maintaining transfer efficiency. We implement and evaluate HAWK on a system built with commercially available GPUs and NPUs, demonstrating performance within 7.88% of a GPU-only system under the same SLO constraints while achieving up to 1.26$\times$ higher power efficiency and 1.72$\times$ higher cost efficiency.
